\subsection{Tiled Program Compilation}
\label{sec:compilation}
%Triton, TileLang, cuTile ...

Tiled program compilation has become a cornerstone of modern deep learning compiler design, fundamentally transforming how tensor computations are mapped onto GPU architectures. The core principle of tiling involves partitioning large-scale tensor operations into smaller, cache-friendly sub-blocks (tiles) that fit within fast on-chip memory, such as shared memory (SMEM) and register files. By iteratively processing these tiles, compilers can maximize data reuse, drastically reduce costly global memory transactions, and expose fine-grained parallelism across GPU streaming multiprocessors (SMs). In the tiled compilation paradigm, high-level computational graphs are systematically decomposed into tile-level execution units, with explicit control over data movement, computation scheduling, and synchronization. This abstraction not only mitigates memory bandwidth bottlenecks but also provides a structured optimization space for hardware-aware kernel generation, laying the groundwork for domain-specific languages (DSLs) that automate low-level GPU programming.

Among the tiled programming works, Triton~\cite{tillet2019triton} has emerged as a paradigm-shifting Python-based DSL and compiler infrastructure, offering a high-level interface that abstracts CUDA complexities while serving as the default backend for PyTorch 2.x's \texttt{torch.compile} (\texttt{TorchInductor}). By translating framework-level IR into optimized GPU kernels through multi-stage transformations and tile-level scheduling, Triton effectively bridges high-level optimizations with hardware execution. Nevertheless, its tile scheduling and memory planning often rely on static heuristics or compile-time auto-tuning, which can struggle to adapt efficiently to highly dynamic tensor shapes and unpredictable runtime memory access patterns. To address hardware-specific tuning needs while preserving Triton compatibility, FlagTree~\cite{zhiyuan25flagtree} introduces TLE (Triton Language Extensions), which provides layered abstractions \texttt{Lite/Struct/Raw} for explicit control over distributed execution and memory access patterns with minimal migration cost.

Recent tiled compilation works further refine scheduling via hardware-aware abstractions. cuTile~\cite{nvidia25cutile} provides a Python-based interface that automatically leverages NVIDIA GPU features (e.g., Tensor Cores, TMAs) while treating tiles as first-class immutable values for fine-grained data movement control. TileLang~\cite{cheng2025pipethreader}, built upon TVM~\cite{chen2018tvm}, addresses the limitation of ad-hoc, operator-specific pipelining in prior works like Triton and CUTLASS~\cite{nvidia22cutlass} by introducing the sTask-graph abstraction, a fine-grained dependency representation that decouples tiling from pipeline scheduling, enabling automatic discovery of efficient schedules for both established patterns (e.g., FlashAttention) and emerging operators. Nevertheless, these approaches still predominantly assume static or profile-determined tensor shapes, leaving dynamic-shape adaptation as an open challenge that motivates our memory-access-guided fusion and shape-adaptive auto-tuning.

\textcolor{red}{
Existing DL compilers~\cite{ansel2024pytorch,abadi2016tensorflow} typically rely on predefined fusion rules that apply only to specific operator combinations, severely limiting the optimization space for dynamic workloads. To navigate this complexity, researchers often classify tensor operators into memory-intensive (MI) and compute-intensive (CI) categories. Early approaches~\cite{zheng2022astitch,niu2021dnnfusion} treat CI operators as non-fusion boundaries, fusing only MI operators to reduce off-chip memory traffic. Subsequent works~\cite{shi2023welder,zheng2023chimera} merge CI operators with adjacent MI ones or decompose CI chains into fine-grained blocks to balance hardware resource utilization. However, these category-based schemes implicitly assume static tensor dimensions and fixed memory access patterns. In practice, operator characteristics and on-chip memory footprints shift significantly with runtime shapes, causing static fusion boundaries to either exceed SMEM capacity or underutilize compute units. Consequently, rigid fusion strategies often yield suboptimal performance when faced with highly variable shape parameters, highlighting the need for memory-aware fusion decisions that adapt to dynamic execution contexts.}

% Search Space Construction
The optimization space for tensor programs is typically constructed via loop-based~\cite{zheng2020ansor,li2023exploiting} or template-based~\cite{xing2022bolt,chen2024evt} methodologies. Loop-based approaches represent operators as deeply nested loops and explore performance through loop transformations (e.g., tiling, unrolling, vectorization). While hardware-portable, they often lag behind vendor-optimized libraries due to limited exposure to hardware-specific instructions (e.g., WMMA, TMA, or warp-level primitives). Conversely, template-based methods leverage vendor-provided building blocks (e.g., CUTLASS~\cite{nvidia22cutlass} or Triton~\cite{tillet2019triton} primitives) to directly map computations to specialized execution units. This hardware-knowledge-driven tuning enables peak performance but introduces significant engineering overhead; extending template coverage to novel fusion patterns or emerging operators remains highly demanding. Moreover, both paradigms struggle to accommodate shape variability: loop schedules require exhaustive re-derivation for new dimensions, while template parameters are typically hard-coded or profiled offline, leaving a critical gap in efficiently scaling search spaces to dynamic tensor programs.

% Auto-tuning Techniques.
To navigate the exponentially large search space, existing auto-tuning frameworks employ rule-based pruning, machine learning-driven cost models~\cite{zheng2021tenset}, or analytical heuristics~\cite{kao2023flat,ragan2013halide}. Learning-based predictors train on extensive runtime profiling data to estimate performance, guiding evolutionary searches (e.g., genetic algorithms or Bayesian optimization) toward high-performing configurations. However, they incur substantial online profiling overhead and lack generalization to unseen shapes or novel fusion boundaries. Analytical models reduce profiling costs by incorporating hardware constraints and program semantics but typically assume fixed operator graphs and static tiling strategies. Aggressive decoupling techniques~\cite{ansel2024pytorch} unfold computation graphs sequentially to reduce search complexity, yet optimizing each operator in isolation without global context frequently leads to suboptimal end-to-end performance. Crucially, prior works rarely provide a unified mechanism to jointly reason about fusion strategies, template selection, and tuning parameters under runtime shape variability, leaving dynamic workloads underserved by static or profile-dependent auto-tuning pipelines.

% DWH：这一段需要昊东 根据ICPP实际使用的方法修改
\textcolor{red}{To address these limitations, our framework introduces a unified approach that combines memory-access-guided fusion with shape-adaptive auto-tuning. Instead of relying on static fusion rules or offline profiling, we analyze memory access patterns at compile time to guide fusion decisions and map candidates to compilation templates derived from Triton~\cite{tillet2019triton} and TileLang~\cite{cheng2025pipethreader}. At runtime, a lightweight residual learning component corrects analytical cost model predictions for unseen shapes, enabling efficient selection of high-performance configurations without exhaustive search.}
